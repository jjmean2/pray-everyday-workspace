# ADR-0002: 서버 DB는 PostgreSQL, ORM은 Drizzle

- **상태**: Accepted
- **날짜**: 2026-10-17
- **관련 요구사항**: R-015, R-016, R-018
- **대체하는 것**: 없음
- **제안 계기**: 사전 설계

## 요약

서버 DB는 PostgreSQL, 서버의 ORM은 Drizzle로 정한다. 동기화(D-06)에 필요한 쿼리(버전 비교를 넣은 조건부 upsert, 삭제 표시, 변경 순번 조회)를 추상화에 막히지 않고 쓸 수 있고, 코드 생성 단계 없이 TypeScript 스키마를 모노리포에서 그대로 쓸 수 있기 때문이다.

## 맥락

처음에는 나중에 만들 앱에서도 같은 ORM으로 기기 DB(SQLite)를 다룰 수 있는지가 가장 큰 기준이었다. 그런데 앱은 iOS와 Android 네이티브로 만드는 쪽을 생각하고 있어서 TypeScript ORM은 서버에서만 쓰인다. 그 기준이 빠지자 차이는 작아졌다.
결정 시점(2026-10)에 두 도구 모두 메이저 전환 중이었다. Prisma는 7이 안정 버전이고 8이 RC로, 쿼리 API가 크게 바뀌고 일부 기능이 아직 없다. Drizzle은 0.45가 안정 버전이고 1.0이 RC다.

## 결정

- 서버 DB는 PostgreSQL이다
- 서버의 데이터 접근은 Drizzle로 한다. 동기화 쿼리는 Drizzle의 SQL 수준 API로 쓴다
- 버전은 구현을 시작할 때 정한다. 그때 Drizzle 1.0이 정식 출시됐으면 1.0으로, 아니면 0.45 안정 버전으로 시작해 1.0으로 올린다

## 검토한 대안

- **Prisma 7**: 스키마 DSL과 관계 쿼리, NestJS 자료가 좋다. 하지만 동기화용 조건부 upsert는 원시 SQL로 내려가야 하고, Prisma 8로 갈 때 쿼리 코드를 다시 써야 한다
- **Prisma 8 (RC)**: 새 API로 시작할 수 있지만 출시 전이고 중첩 쓰기, `$extends` 같은 기능이 아직 없다
